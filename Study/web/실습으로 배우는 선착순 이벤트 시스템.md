# 강의 목표
- 선착순 100명에게 할인쿠폰을 제공하는 시스템을 만들며 동시성, 부하 분산에 대해 학습한다.
- 순간적으로 몰리는 트래픽을 버틸 수 있는 시스템을 만드는 것을 가정한다.

# 1. 동시성 문제
- 쿠폰 발급 API에서 선착순 100명에게 쿠폰을 발급했는지 확인하려면 if문 만으로는 해결하지 못한다.
- 여러 요청이 동시에 같은 자원에 접근하는 race condition이 발생하기 때문에 정확히 100개를 발급하지 못한다.
- 간단하게는 application에서 lock을 걸 수도 있지만, 그렇게 하면 여러 서버로 분산되어 있는 환경에서는 race condition이 발생한다.
- 그래서 redis를 활용하여 이 문제를 해결한다. redis의 원자적 연산인 incr 명령을 사용하여 쿠폰 발급 개수를 카운팅한다.
- redis는 싱글 스레드 기반이기 때문에 여러 애플리케이션에서 요청하더라도 race condition이 발생하지 않는다.
- redis를 사용하여 동시성 문제는 해결하였다. 하지만 동시에 트래픽이 과도하게 몰리는 이러한 상황에서 쿠폰 발급 결과를 DB에 매번 저장하는 것은 DB에 많은 부하를 발생시킨다. 이러한 문제는 kafka와 같은 메시지 브로커를 사용하여 해결 가능하다.

# 2. 부하 분산
- 메시지 브로커(이하: Kafka)를 사용하면 DB 부하를 줄일 수 있다.
- 1만개의 쿠폰을 선착순 발급한다고 가정해보자. API 서버가 분산되어 있는 환경에서 하나의 DB를 사용한다고 하면 DB에 1만개의 insert 요청이 동시다발적으로 발생할 것이다. 그런데 Kafka를 사용하면 Kafka에 메시지만 1만개가 쌓이고, Consumer 프로세스가 순차적으로 메시지를 받아서 처리하기 때문에 1만개의 insert 요청이 순차적으로 이뤄진다. 그렇기 때문에 Kafka를 사용하면 DB 부하를 줄일 수 있다.
