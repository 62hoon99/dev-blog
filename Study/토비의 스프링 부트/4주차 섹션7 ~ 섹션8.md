# @Conditional – 상황에 맞는 빈 등록
스프링 부트에서는 같은 인터페이스를 구현한 컴포넌트가 여러 개 존재할 수 있다. 이때 특정 환경, 설정, 조건에 따라 필요한 구현체만 빈으로 등록하고 싶을 때 @Conditional 계열 어노테이션을 사용한다.

@Conditional은 조건 클래스를 평가해 true일 경우에만 해당 빈을 컨테이너에 등록한다. 덕분에 런타임 환경, 설정 값, 프로파일, 특정 클래스 존재 여부 등에 따라 유연하게 빈 구성을 제어할 수 있다.

대표적으로 다음과 같은 형태로 활용할 수 있다.
- 특정 설정 값이 있을 때만 빈 등록
- 특정 클래스가 클래스패스에 존재할 때만 빈 등록
- 프로덕션 / 로컬 / 테스트 등 환경에 따라 구현체 선택
- 여러 구현체 중 조건에 맞는 것만 선택적으로 활성화

이를 통해 같은 인터페이스를 사용하는 의존성이라도 상황에 맞는 구현체를 안전하게 주입받을 수 있으며, 확장성과 가독성이 높은 구성 설정을 만들 수 있다.

## @Conditional 실무 적용 예시
현재 재직 중인 회사의 소프트웨어는 여러 버전으로 배포되고 있으며, 내가 담당하고 있는 스프링 부트 기반 모듈은 모든 버전을 지원해야 한다.

이 모듈은 실행 시 소프트웨어의 버전을 확인하고, 해당 버전에 맞는 빈을 등록한다. (예: 7버전이면 Version7 빈 등록)

버전에 따라 동작이 달라져야 하는 컴포넌트들은 버전별 구현 클래스를 따로 만들고, @Conditional을 적용해 해당 버전에 맞는 구현체만 빈으로 등록되도록 구성했다. 이를 통해 하나의 모듈로 여러 제품 버전을 안정적으로 지원할 수 있었다.

## Web Application Conditions 실무 적용 예시
@ConditionalOnWebApplication은 현재 환경이 웹 애플리케이션인지 여부를 기준으로 빈을 등록할 수 있는 기능이다.

회사에서 개발한 스프링 부트 기반 사내 라이브러리에서는 요청자의 이름을 로그에 남겨야 했다.
- 웹 애플리케이션 환경: 요청마다 요청자가 다르기 때문에 요청 단위로 요청자 정보를 관리해야 했다.
- 비웹 환경: 요청자가 고정되므로 고정된 값을 사용하면 된다.

이를 위해 @ConditionalOnWebApplication / @ConditionalOnNotWebApplication 을 사용해 환경에 따라 다른 구현체가 빈으로 등록되도록 구성했고, 또한 웹 환경에서는 요청마다 Context를 초기화하기 위해 @RequestScope를 적용하여 요청 단위로 Context가 관리되도록 처리했다.
