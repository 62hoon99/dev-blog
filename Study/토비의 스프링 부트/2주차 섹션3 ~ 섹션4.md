# Front Controller (Dispatcher Servlet)

### 서블릿 접근방법 문제

- 서블릿이 여러개로 늘어나고 모든 서블릿이 컨테이너로부터 요청을 직접 받아서 모든 작업을 다 수행하고 리턴하는 방식으로 개발하다 보니 모든 서블릿에서 공통으로 필요로 하는 어떤 작업이 각 서블릿 코드 안에 중복되어서 등장함.
- request object 와 response object 를 다루어야 하기 때문에 기본적인 서블릿만 가지고는 개발하기 어려움
- 그래서 등장한게 front controller

### front controller

- 제일 앞단에 있는 오브젝트에서 공통적인 작업을 다 처리하고 요청의 종류에 따라서 이 로직을 처리하는 다른 오브젝트한테 요청을 다시 위임해서 전달하는 방식으로 구현하게 함
- 후처리도 담당함

### 요청의 3요소

- http method
- path url
- header, body

### 응답의 3요소

- http status
- content type
- header, body

### 매핑과 바인딩

매핑

- http mothod, path url 에 맞는 요청에 대응하는 로직을 처리하는 작업

바인딩

- 파라미터로 넘어온 값을 Java 타입에 맞추어서 변환 후 인자 값으로 넘겨주는 작업

# 독립 실행형 어플리케이션

## DI
![[toby-springboot-assembler.png]]
- HelloController 가 SimpleHelloService 를 의존하면 ComplexHelloService 로 Service 객체를 변환해야 할 때 HelloController 코드도 같이 변환해야한다. 이러한 번거로움을 피하기 위해 interface 를 만들어서 의존한다.
- 런타임에는 HelloService 의 구현체로 무슨 객체를 의존해야 하는지 정해주어야 한다. 이는 HelloController 가 정하는게 아니라 제 3의 객체가 지정을 해주어야 하는데 이를 **Assembler** 라고 한다.
- 이 **Assembler** 를 Spring에서는 **Spring Container** 라고 부른다.
- Spring Container 를 사용해야 하는 주된 이유는 빈 들의 의존관계를 알아서 주입해주고 관리해주기 때문이다.

## Dispatcher Servlet
- 스프링 컨테이너는 빈 들을 돌아다니면서 매핑 할 수 있는 빈을 찾는다. 그렇기 때문에 클래스 단위에 Mapping 할 수 있는 클래스라고 알려줄 수 있는 어노테이션이 필요하다.
- Spring 의 기본 동작은 View 라고 불리는 HTML 템플릿을 반환하게 된다. 그래서 이 값을 보여줄 view 를 찾는다. view 가 없을 경우 404 에러를 띄운다.

## 매개변수로 주입 받기
- Bean으로 등록하고 싶은 객체를 반환하는 메서드에 @Bean 어노테이션을 붙여서 사용할 때 해당 Bean 이 의존하는 다른 Bean이 있다면 매개변수로 받으면 된다.
    - SpringContainer한테 내가 Java 코드로 HelloController를 만들텐데 필요한 의존 오브젝트를 주입해줘~ 하면 된다.

## @Configuration
- Configuration이 붙은 클래스가 AnnotationConfig를 이용하는 애플리케이션 컨텍스트에 처음 등록된다.
    - 왜나하면 Configuration이 붙은 클래스는 BeanFactoryMethod를 가지는 것 이상으로 전체 애플리케이션을 구성하는데 필요한 중요한 정보를 많이 넣을 수 있기 때문에 그렇다.

## @ComponentScan
- 컴포넌트 스캔이 붙어 있으면 이 클래스가 있는 패키지부터 시작해서 그 하위 패키지를 뒤져서 컴포넌트라는 애노테이션이 붙은 모든 클래스를 빈으로 등록을 해버린다.
- 새로운 빈을 만들어서 추가할 때 매번 어디다가 이 구성정보를 다시 등록해줄 필요가 없이 내가 작성하는 클래스가 빈으로 등록되어진다.

### @ResponseBody
- API로서 기능을 하는 컨트롤러 메서드를 만들 때는 컨트롤러 메서드가 리턴하는 값을 그대로 응답의 body에 넣어서 응답하는 방식을 사용한다.

## 라이프 사이클 메서드
- ApplicationContextAware 인터페이스를 구현하면 스프링 컨테이너가 초기화 되는 시점에 스프링이 setter 메서드를 호출해서 bean을 알아서 주입해준다.
- 요즘에는 생성자의 매개변수로 받아서 사용하는 방법을 사용하는게 좋다. 이 라이프 사이클 메서드는 예전에 나온 기법이다.(setter 사용)

### 플로우 정리

외부로 부터 온 요청을 apache(web server) 가 받아서 servlet container(tomcat) 에게 넘기면 container 가 해당 요청을 담당하는 servlet 을 찾아서 요청을 넘겨준다. 서블렛은 HTTP 요청을 처리하고 이 요청을 처리하는 spring bean을 호출한다.

### 서블릿 컨테이너가 하는 일
1. **라이프사이클 관리**: 서블릿 컨테이너는 서블릿의 인스턴스 생성, 초기화, 서비스 및 소멸과 같은 라이프사이클을 관리합니다.
2. **요청 처리**: 클라이언트로부터 오는 HTTP 요청을 받아들이고, 해당 요청을 처리하기 위해 적절한 서블릿에게 전달합니다. 이때 서블릿은 요청을 처리하고 응답을 생성하여 다시 컨테이너로 보냅니다.
3. **스레드 관리**: 여러 클라이언트로부터 오는 동시 요청을 처리하기 위해 스레드 풀을 사용하여 효율적으로 자원을 관리합니다. 이는 다수의 요청을 동시에 처리할 수 있도록 합니다.
4. **세션 관리**: HTTP는 기본적으로 상태를 유지하지 않는 stateless 프로토콜이지만, 서블릿 컨테이너는 세션 관리를 통해 클라이언트의 상태를 추적하고 유지할 수 있도록 합니다.
5. **보안**: 보안 관련 기능을 제공하여 인증, 권한 부여 및 암호화와 같은 보안 요구 사항을 처리합니다.
