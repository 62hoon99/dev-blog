# 8.1 디스크 I/O

데이터베이스의 성능 튜닝은 어떻게 디스크 I/O를 줄이느냐가 관건일 때가 상당히 많다.

---

## 8.1.1 하드 디스크 드라이브(HDD)와 솔리드 스테이트 드라이브(SSD)

HDD는 자기 원판(플래터)을 물리적으로 회전시켜 데이터를 읽고 쓰는 방식이다. 반면 SSD는 플래시 메모리 기반으로 기계적인 회전 없이 전기 신호로 데이터를 처리한다.

데이터베이스의 병목은 CPU/메모리보다 디스크 I/O에서 발생하는 경우가 많기 때문에, 저장 매체의 특성 차이가 성능에 직접적인 영향을 준다.

|특성|HDD|SSD|
|---|---|---|
|저장 방식|자기 플래터 회전|플래시 메모리 (전기 신호)|
|랜덤 I/O 성능|낮음 (헤드 이동 필요)|높음 (물리적 이동 없음)|
|순차 I/O 성능|비교적 양호|매우 빠름|
|탐색 시간(seek time)|있음 (ms 단위)|거의 없음|
|내구성|충격에 취약|충격에 강함|
|가격 (GB당)|저렴|상대적으로 높음|
|용량|대용량 유리|점점 따라오는 추세|

> 📊 **벤치마크** : SSD는 초당 436개의 트랜잭션을 처리했지만, HDD는 초당 60개의 트랜잭션 처리에 그쳤다. 약 **7배**의 성능 차이다.

특히 SSD는 **랜덤 I/O 성능**에서 압도적인 차이를 보인다. DB 서버에서 발생하는 I/O 패턴 대부분이 랜덤 I/O이기 때문에, SSD 도입 시 체감 성능 향상이 크다.

---

## 8.1.2 랜덤 I/O와 순차 I/O

### 개념

- **순차 I/O (Sequential I/O)** : 디스크의 연속된 주소 공간에 순서대로 읽고 쓰는 방식
- **랜덤 I/O (Random I/O)** : 디스크의 여러 주소를 불규칙하게 접근하는 방식

### 차이 비교

|순차 I/O|랜덤 I/O|
|---|---|---|
|접근 패턴|연속된 블록을 순서대로 접근|임의의 위치 블록을 산발적으로 접근|
|HDD 특성|빠름 (헤드 이동 최소)|느림 (헤드 이동이 빈번하게 발생)|
|SSD 특성|빠름|빠름 (HDD 대비 큰 차이 없음)|
|MySQL 사용 예|풀 테이블 스캔, 백업|인덱스 탐색, 특정 행 조회|

### HDD에서 랜덤 I/O가 느린 이유

HDD는 데이터를 읽으려면 다음 3단계를 거친다.

```
1. Seek Time   : 헤드가 해당 트랙으로 이동
2. Rotational Latency : 플래터가 회전해 목표 섹터가 헤드 아래로 올 때까지 대기
3. Transfer Time : 실제 데이터 읽기/쓰기
```

랜덤 I/O는 매 접근마다 **Seek Time + Rotational Latency**가 반복되기 때문에 지연이 누적된다. 반면 순차 I/O는 헤드가 제자리에서 데이터를 연속으로 읽어나가므로 이 오버헤드가 거의 없다.

### MySQL 쿼리 최적화와의 연관성

> MySQL에서 인덱스를 사용하는 것은 기본적으로 랜덤 I/O를 발생시킨다. 쿼리를 튜닝한다는 것은 결국 **랜덤 I/O 자체를 줄이는 것**, 또는 **순차 I/O로 전환하는 것**을 의미한다.

- 인덱스 레인지 스캔 → 랜덤 I/O
- 풀 테이블 스캔 → 순차 I/O
- **인덱스가 항상 빠른 건 아니다** : 읽어야 할 데이터가 전체의 20~25% 이상이 되면, MySQL 옵티마이저는 풀 테이블 스캔(순차 I/O)을 선택하는 것이 오히려 빠를 수 있다고 판단한다.
