# 실습 1 — 복합 인덱스 설계와 filesort 제거

**시나리오**: "현재 재직 중인 개발팀 직원을 연봉 높은 순으로 조회"

```sql
SELECT id, emp_no, name, position, salary
FROM employees
WHERE department = '개발팀'
  AND status = 'ACTIVE'
ORDER BY salary DESC
LIMIT 50;
```

**실습 목표**
- 인덱스 없을 때 실행 계획과 실행 시간을 먼저 기록한다
- 인덱스를 직접 설계하고 적용해서 실행 계획이 어떻게 바뀌는지 확인한다
- `Using filesort` 를 제거하는 인덱스를 찾아본다

**힌트**
- 컬럼 순서를 다르게 바꿔가며 실행 계획을 비교해본다
- `ORDER BY salary DESC` 를 인덱스가 처리하려면 인덱스 선언 시 어떻게 해야 할까?
- `EXPLAIN` 의 `type`, `key`, `rows`, `Extra` 를 기록해두고 비교한다

# 실습 1 - 실습 내용 정리

## 인덱스 없을 때

## 인덱스 있을 때

### where 조건에 포함되는 두 컬럼을 기준으로 복합 인덱스

```
-- 복합 인덱스 (추천)
CREATE INDEX idx_department_status ON employees (department, status);
```

#### 실행계획
- index는 탔지만 filesort를 하는 걸 확인할 수 있다.
- type이 ref로 바뀌었다.

**항목별 분석**

| 항목         | 값                       | 해석                       |
| ---------- | ----------------------- | ------------------------ |
| `type`     | `ref`                   | 인덱스 정상적으로 탐 ✅            |
| `key`      | `idx_department_status` | 예상대로 인덱스 사용 ✅            |
| `rows`     | 155,290                 | 인덱스 타고도 **15만 행** 읽음 ⚠️  |
| `filtered` | 100%                    | WHERE 조건은 완벽히 필터링 ✅      |
| `Extra`    | `Using filesort`        | **메모리/디스크에서 별도 정렬 발생** ❌ |

```
*************************** 1. row ***************************
           id: 1
  select_type: SIMPLE
        table: employees
   partitions: NULL
         type: ref
possible_keys: idx_department_status
          key: idx_department_status
      key_len: 164
          ref: const,const
         rows: 155290
     filtered: 100.00
        Extra: Using filesort
```

#### 소요 시간
- 210 ms 로 줄었다

```
|       14 | 0.21099450 | SELECT id, emp_no, name, position, salary  FROM employees  WHERE department = '개발팀' AND status = 'ACTIVE'  ORDER BY salary DESC LIMIT 50            |
```

### where 조건에 포함되는 두 컬럼 + 정렬 컬럼

```
CREATE INDEX idx_department_status_salary ON employees (department, status, salary DESC);
```

#### 실행 계획
- filesort가 사라졌다

```
*************************** 1. row ***************************
           id: 1
  select_type: SIMPLE
        table: employees
   partitions: NULL
         type: ref
possible_keys: idx_department_status,idx_department_status_salary
          key: idx_department_status_salary
      key_len: 164
          ref: const,const
         rows: 155290
     filtered: 100.00
        Extra: NULL
```

#### 소요 시간
- 3ms 로 엄청나게 줄었다!

```
|        9 | 0.00317575 | SELECT id, emp_no, name, position, salary  FROM employees  WHERE department = '개발팀' AND status = 'ACTIVE'  ORDER BY salary DESC LIMIT 50            |
```
