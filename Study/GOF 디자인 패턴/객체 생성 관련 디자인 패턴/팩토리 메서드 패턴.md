>구체적으로 어떤 인스턴스를 만들지는 서브 클래스가 정한다

# 팩토리 메서드 패턴의 필요성
- 비슷한 유형의 객체가 계속 추가될 가능성이 있는 경우, 객체 생성을 기존 코드에서 직접 처리하면 새로운 타입이 늘어날 때마다 코드를 수정해야 한다.
- 팩토리 메서드 패턴은 객체 생성 책임을 팩토리로 분리함으로써, 기존 코드를 변경하지 않고 새로운 객체를 추가하는 방식으로 확장할 수 있다.
- 이를 통해 OCP(Open-Closed Principle, 개방-폐쇄 원칙)을 준수할 수 있다.

# 팩토리 메서드 패턴 구현 예시

## Factory
``` Java
public interface ShipFactory {  
  
    default Ship orderShip(String name, String email) {  
        validate(name, email);  
        prepareFor(name);  
        Ship ship = createShip(name);  
        sendEmailTo(email, ship);  
        return ship;  
    }  
  
    private void sendEmailTo(String email, Ship ship) {  
        System.out.println("주문하신 배 " + ship + "의 완료 정보를 " + email + "로 보냅니다.");  
    }  
  
    Ship createShip(String name);  
  
    private void validate(String name, String email) {  
        if (name == null || name.isBlank()) {  
            throw new IllegalArgumentException("배 이름을 지어주세요.");  
        }  
        if (email == null || email.isBlank()) {  
            throw new IllegalArgumentException("연락처를 남겨주세요.");  
        }  
    }  
  
    private void prepareFor(String name) {  
        System.out.println(name + " 만들 준비 중");  
    }  
  
}
```

``` Java
public class BlackShipFactory implements ShipFactory {  
  
    @Override  
    public Ship createShip(String name) {  
        return new BlackShip(name, "black", "검정 배");  
    }  
}

public class WhiteShipFactory implements ShipFactory {  
  
    @Override  
    public Ship createShip(String name) {  
        return new WhiteShip(name, "white", "흰 배");  
    }  
}
```

## Ship
``` Java
public abstract class Ship {  
    protected String name;  
    protected String color;  
    protected String description;  
  
    public Ship(String name, String color, String description) {  
        this.name = name;  
        this.color = color;  
        this.description = description;  
    }  
  
    @Override  
    public String toString() {  
        return description;  
    }  
}
```

``` Java
public class BlackShip extends Ship{  
  
    public BlackShip(String name, String color, String description) {  
        super(name, color, description);  
    }  
}

public class WhiteShip extends Ship {  
    public WhiteShip(String name, String color, String description) {  
        super(name, color, description);  
    }  
}
```

## Client
``` Java
public class Client {  
  
    public static void main(String[] args) {

# 팩토리 메서드 패턴 복습

**팩토리 메소드 패턴을 적용했을 때의 장점은? 단점은?**
> 장점: 비슷한 유형의 객체가 추가되더라도 코드를 수정하지 않고 추가가 가능하다. 이로써 OCP 원칙을 준수할 수 있다.
> 단점: 클래스 종류가 늘어나서 관리가 어려워 진다.

**“확장에 열려있고 변경에 닫혀있는 객체 지향 원칙”을 설명하세요.**
> 비슷한 유형의 객체가 추가되면 코드를 수정해야 하는 클래스 구조 또는 설계가 아니라 기존 코드 수정 없이 코드를 추가하는 방식이 되어야 한다는 원칙. 왜냐하면 기존 코드를 수정한다는 것은 기존에 정상동작하던 로직에 장애를 일으킬 수 있고, 코드도 더러워지기 때문에.

**자바 8에 추가된 default 메소드에 대해 설명하세요.**
> interface에 직접 로직을 작성할 수 있는 메서드. 자바 8에서 Stream을 컬렉션 프레임워크에 추가하기 위해 도입. Stream은 자료구조 종류에 상관없이 동일한 기능을 제공하기 때문에 default 메서드에 적합. 자바 9에서는 interface에 private 메서드 또한 작성할 수 있게 되었음.

**Collection Interface의 stream() 메서드**
```
@Override  
default Spliterator<E> spliterator() {  
    return Spliterators.spliterator(this, 0);  
}

 * for details.) * * @implSpec  
 * The default implementation creates a sequential {@code Stream} from the  
 * collection's {@code Spliterator}.  
 * * @return a sequential {@code Stream} over the elements in this collection

 */default Stream<E> stream() {
