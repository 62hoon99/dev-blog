# 빌더 패턴
**장점**
- 필드 중 optional 한 값이 있어서 생성자를 여러개 만들어야 하는 경우에 빌더 패턴을 사용하면 생성자를 여러개 만들지 않아도 된다.
- 복잡한 객체를 만드는 구체적인 과정을 숨길 수 있다.
**단점**
- 원하는 객체를 만들려면 빌더부터 만들어야 한다.
- 복잡해진다. (트레이드 오프)

(코드 생략, Lombok의 @Builder를 많이 쓰니까 넘어간다.)

# 스텝 빌더 패턴 (강의에 없는 내용)
## 스텝 빌더 패턴이란?

- 빌드 과정을 **단계(Step)** 로 나눈다.
- 각 단계는 **다음 단계 인터페이스만 반환**한다.
- 빌드 순서를 **강제로 지키게 (컴파일 타임 보장)**한다.

## 스텝 빌더 패턴 구현 예시

**Builder**
``` Java
public class User {

    private final String name;
    private final String email;
    private final int age;

    private User(String name, String email, int age) {
        this.name = name;
        this.email = email;
        this.age = age;
    }

    // Step 1
    public interface NameStep {
        EmailStep name(String name);
    }

    // Step 2
    public interface EmailStep {
        OptionalStep email(String email);
    }

    // Step 3 (선택)
    public interface OptionalStep {
        OptionalStep age(int age);
        User build();
    }

    // 실제 Builder
    public static class Builder
            implements NameStep, EmailStep, OptionalStep {

        private String name;
        private String email;
        private int age = 0;

        @Override
        public EmailStep name(String name) {
            this.name = name;
            return this;
        }

        @Override
        public OptionalStep email(String email) {
            this.email = email;
            return this;
        }

        @Override
        public OptionalStep age(int age) {
            this.age = age;
            return this;
        }

        @Override
        public User build() {
            return new User(name, email, age);
        }
    }

    public static NameStep builder() {
        return new Builder();
    }
}
```

**Client**
``` Java
// 가능
User user = User.builder()
    .name("kihoon")
    .email("kihoon@example.com")
    .age(30)
    .build();

// 불가능
User.builder().email("test");   // name 먼저 호출 안 됨
User.builder().name("a").build(); // email 필수
```

## Spring 예시

**Spring WebClient**
``` Java
webClient.post()
    .uri("/users")
    .header("Authorization", token)
    .bodyValue(requestBody)
    .retrieve()
    .bodyToMono(User.class);
```

- post() → uri() → body() → retrieve()
- 각 단계마다 **반환 타입이 달라진다.**
- 스텝 빌더 패턴을 적용하여 잘못된 호출 순서를 방지한다.
