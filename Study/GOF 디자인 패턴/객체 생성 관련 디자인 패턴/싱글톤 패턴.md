# 싱글톤 구현 방법

## 1. 이른 초기화 방법

**코드**
``` Java
public class Settings {  
    private static final Settings instance = new Settings();  
      
    private Settings() {}  
      
    public static Settings getInstance() {  
        return instance;  
    }  
}
```

**특징**
- 프로그램 실행 중 JVM이 클래스를 로딩할 때 인스턴스가 생성된다. (불필요하게 사용하지도 않는데 생성될 수 있음)
- thread safe 하다.

## 2. Double Checked Locking

**코드**
``` Java
public class Settings {  
    private static volatile Settings instance;  
  
    private Settings() {}  
  
    public static Settings getInstance() {  
        if (instance == null) {  
            synchronized (Settings.class) {  
                if (instance == null) {  
                    instance = new Settings();  
                }  
            }  
        }  
        return instance;  
    }  
}
```

**특징**
- 지연 로딩. 인스턴스를 사용하는 시점에 로딩된다.
- synchronized 키워드를 인스턴스 생성 시점에만 쓰기 때문에 synchronized 키워드를 메서드 단위로 쓰는 것 보다 성능에 이점이 있다.
- volatile을 쓰는 이유는 가시성 문제.

## 3. Static Inner Class

**코드**
``` Java
public class Settings {  
      
    private Settings() {}  
      
    private static class SettingsHolder {  
        private static final Settings instance = new Settings();  
    }  
      
    public static Settings getInstance() {  
        return SettingsHolder.instance;  
    }  
}
```

**특징**
- 지연 로딩. 인스턴스를 사용하는 시점에 로딩된다.
- thread safe 하다.

# 싱글턴 패턴 구현 깨트리는 방법

1. 리플렉션 사용
	- 리플렉션: 구체적인 클래스 타입을 알지 못해도, 런타임에 클래스의 정보(메서드, 필드, 생성자 등)를 분석하고 조작할 수 있게 해주는 API
2. 직렬화 & 역직렬화 사용

싱글턴 패턴이 절대 깨지지 않는 방법은?: Enum

## Enum
- Enum: 서로 연관된 상수들의 집합을 단순한 정수값을 넘어 하나의 클래스처럼 정의하여, 타입 안전성(Type Safety)과 풍부한 기능을 보장하는 특수한 데이터 타입
- Enum은 원래 싱글턴
- 이른 초기화라는 단점이 존재한다.

# 싱글턴 패턴 복습

**자바에서 enum을 사용하지 않고 싱글톤 패턴을 구현하는 방법은?** 
> 이른 초기화 방식, Double Checked Lock, static inner class 방식


**private 생성자와 static 메소드를 사용하는 방법의 단점은?** 
> synchronized 키워드를 붙여야 thread safe 해진다. 이른 초기화 방식을 사용하면 인스턴스를 사용하지 않더라도 생성되는 단점이 존재한다.

**enum을 사용해 싱글톤 패턴을 구현하는 방법의 장점과 단점은?** 
> 장점: 싱글턴 깨트리기 불가능, 단점: 상속(extends) 사용 불가, 이른 초기화
