# DI와 테스트 어노테이션 활용
### 컨테이너 인프라스트럭처 빈

- 컨테이너가 직접 등록하는 빈

### 애플리케이션 빈
- 개발자가 구성 정보를 제공해야 하는 빈
- 애플리케이션 로직 빈, 애플리케이션 인프라스트럭처 빈 으로 나뉜다.
    - 애플리케이션 로직 빈은 우리가 개발할 때 만드는 빈
    - 애플리케이션 인프라스트럭처 빈은 보통 만들어져 있는 빈을 사용
- 사용자 구성정보 (ComponentScan)
    - controller, decorator, service .. bean
- 자동 구성정보 (AutoConfiguration)
    - TomcatServletWebServerFactory, DispatcherServlet

# 자동 구성 기반 애플리케이션
## 메타 에너테이션
에너테이션에 적용한 에너테이션을 메타 에너테이션이라고 부른다. 스프링은 메타 에너테이션의 효력을 적용해준다. @Service 어노테이션을 보면 @Component가 붙어 있는 걸 볼 수 있다. 그래서 @Service 어노테이션을 붙이면 컴포넌트 스캔 대상에 포함되어 컴포넌트로 등록 되었던 것이다.

## 합성 에너테이션
하나 이상의 메타 애노테이션이 적용된 애노테이션을 합성 에너테이션이라고 부른다. 합성 애노테이션을 사용하면 모든 메타 애노테이션이 적용된 것과 동일한 효과를 갖는다.

## 인프라 빈 구성 정보의 분리
@Import를 사용하면 컴포넌트 스캔 대상이 아닌 클래스도 빈으로 등록할 수 있다.
예를 들어 비동기 프로그래밍을 위해 @Async를 사용하려면 @EnableAsync를 @Configuration 클래스에 추가해야 한다. @EnableAsync를 확인해보면 내부에서 @Import를 사용하고 있는데, 이는 스프링이 기본적으로 비동기 기능을 제공하더라도 **비동기 기능을 실제로 사용할 때만 관련 빈을 등록**하도록 의도한 설계임을 보여준다.

``` java
@Target(ElementType.TYPE)  
@Retention(RetentionPolicy.RUNTIME)  
@Documented  
@Import(AsyncConfigurationSelector.class)  
public @interface EnableAsync { ... }
```
