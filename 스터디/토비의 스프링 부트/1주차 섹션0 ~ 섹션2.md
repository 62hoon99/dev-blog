# 강의 소개

- 스프링 부트는 스프링을 사용하는 방법에 대한 강한 의견이 반영된 프레임워크이자 도구이다.

---

# 학습방법

- 스프링 부트를 사용하면 내가 모르는 채로 무슨 일이 일어나고 있는지에 대해 잘 알 수 없다.
- 스프링 부트가 스프링을 어떻게 이용해서 동작하는지를 코드를 통해서 설명할 수 있는 방법을 연구해서 강의로 만들었다.

# 스프링 부트 살펴보기

- 스프링 부트는 스프링을 기반으로 실무 환경에 사용 가능한 수준의 독립실행형 애플리케이션을 **복잡한 고민 없이 빠르게 작성할 수 있게 도와주는 여러가지 도구의 모음**이다.
- 스프링 부트는 스프링을 사용하면서 부수적으로 해야 했던 일을 안하고 바로 개발 할 수 있게 해준다.
- 빠르게 많은 부분들을 고민하지 않고 개발할 수 있다는 거는 스프링 부트가 정해주겠다는 뜻이다.
- 앱을 빠르게 출시하는데는 좋지만, 대규모 서비스로 확장하다보면 한계에 부딪힌다.
- [start.spring.io](http://start.spring.io) 에 있는 버전은 스프링 부트의 버전이다. 스프링 버전과 스프링 부트 버전은 엄연히 다르다.

**스프링 부트의 핵심 목표**

- 프로젝트에서 필요로 하는 다양한 비기능적인 기술(내장형 서버, 보안, 메트릭, 상태 체크 등) 제공
- 스프링 부트는 강한 자기주장을 한다. (기본 설정이 다 되어있기 때문에)
    - 하지만 사용자가 커스텀 할 수 있다.
- 스프링은 xml 설정을 필요로하지만 스프링 부트는 xml을 사용하지 않는 방식을 추구한다.

**스프링 부트는 컨테이너리스 웹 애플리케이션 아키텍처를 지원해달라는 한 개발자의 요청으로 시작했다.**

## Containerless

- 서버리스와 유사하다
- 서버에 대한 설치를 사용자가 신경쓰지 않아도 되도록 해달라는 뜻
- 스프링은 IOC 컨테이너이다. 여기서 말하는 컨테이너는 스프링 컨테이너가 아니다.
- 웹 컴포넌트는 웹 클라이언트가 요청을 주어야 일을 한다. 웹 컴포넌트는 동적인 컨텐츠를 보여주기 위해서 사용한다.
- 웹 컴포넌트는 웹 컴포넌트 독립적으로 있을 수 없다. 웹 컨테이너 안에 있어야 된다.
    - 웹 컴포넌트를 관리해주는 애가 웹 컨테이너
    - 웹 컨테이너는 여러 종류의 웹 컴포넌트를 관리한다.
    - 요청이 들어오면 웹 컨테이너는 라우팅, 매핑 과정을 통해서 담당하는 웹 컴포넌트에게 보내준다.
    - spring 에서 **웹 컨테이너는 서블릿 컨테이너**이다. (소름)
        - spring boot 에서는 기본적으로 톰캣 서블릿 컨테이너를 사용
    - spring 에서 **웹 컴포넌트는 서블릿**이다.
    - spring 컨테이너는 서블릿 컨테이너 뒤에 존재한다.
    - 서블릿, 서블릿 컨테이너는 디게 복잡하고 설정할게 정말 많음.
        - 개발할 때 중요한 내용이 아니고 프로젝트의 시작 때만 만들고 신경쓰지 않음
    - 서블릿 컨테이너는 하나만 있는게 아님
        - 여러 제품이 있는데 제일 유명한게 톰켓임
        - 배포방식, 설정이 제품마다 다 다름
        - 이 것 때문에 러닝커브가 높음
- 여기서 말하는 컨테이너는 서블릿 컨테이너이다.
    - 서블릿 컨테이너를 아예 안쓰는게 아니라, 서블릿 컨테이너 설치랑 관리를 하지 않고 개발할 수 있게 개발해달라는 것이다.
    - 서블릿 컨테이너를 띄우는 작업도 부트가 해준다.
- 스프링 부트는 메인 메서드를 실행시키면 알아서 서블릿 컨테이너가 띄어진다.
    - 이를 독립 실행형 어플리케이션, 스탠드얼론 애플리케이션이라고 부른다.

# Opiniontated

**내가 다 정해줄게 일단 개발만 해**

### 스프링 프레임워크의 설계 철학

- 극단적인 유연함 추구
- 다양한 관점을 수용
- Not opinionated
- 수많은 선택지를 다 포용

문제 → 고민을 다 개발자가 해야됨

### 스프링 부트의 설계 철학

- **Opioniontated** - 자기 주장이 강한, 자기 의견을 고집하는, 독선적인
- 일단 정해주는 대로 빠르게 개발하고 고민은 나중에
- 스프링을 잘 활용하는 뛰어난 방법을 제공
- 업계에서 검증된 스프링 생태계 프로젝트, 표준 자바 기술, 오픈소스 기술의 종류와 의존관계, 사용 버전을 정해줌
- 각 기술을 스프링에 적용하는 방식 (DI 구성)과 디폴트 설정값 제공

### 유연한 확장

- 스프링 부트에 내장된 디폴트 구성을 커스터마이징 하는 매우 자연스럽고 유연한 방법 제공
- 원하는 방식으로 재구성이 가능하다.
- 나만의 스프링 부트 모듈 만들기가 가능하다.

## 강의의 목표

- 스프링 부트로 만든 스프링 애플리케이션의 기술과 구성 정보를 직접 확인할 수 있다.
- 적용 가능한 설정 항목을 파악할 수 있다.
- 직접 만든 빈 구성 정보를 적용하고, 그에 따른 변화를 분석 할 수 있다.
- 스프링부트의 기술을 꼼꼼히 살펴볼 수 있다.
