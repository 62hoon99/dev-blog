# 문제
대량의 트래픽이 몰리는 경우 선착순 쿠폰 발급 기능에 지연이 발생한다.

![[Pasted image 20251214131801.png]]
# 원인
대량의 트래픽이 몰리는 경우 쿠폰 발급 처리를 위한 조건 체크 중 **발급 수량 부분**에서 DB와 경합이 발생한다.
- 글에는 나와있지 않으나, 선착순 쿠폰 발급 시 발급된 쿠폰 개수를 확인해야 하고, 한 사용자가 중복 발급하지 않도록 해야 하는데 이 과정은 원자적으로 이루어져야 하다보니 지연이 발생한다는 것으로 이해된다.

# 해결
![[Pasted image 20251214132920.png]]
DB에서 쿠폰 발급 수량을 확인하지 않고, 쿠폰 발급 수량을  캐싱하여(Redis 이용) 지연 현상을 완화했다.
- 글을 읽고 이해가 잘 되지 않는 점들이 많다. 트랜잭션 처리와 동시성 제어를 하기 위해서는 Redis에 쿠폰 발급 Lock을 하나 생성하고, Redis에 쿠폰 발급 수량을 체크하기 전에 Redis에서 Lock을 점유한 다음 Redis에서 쿠폰 발급 수량을 확인하고, 발급 조건 검사를 해야 될 것으로 생각된다. 그렇다면 선착순 쿠폰이 모두 발급되기 전까지는 지연 현상이 계속되고, 선착순 쿠폰 발급이 완료된 후에는 지연 현상이 개선되었을 것으로 예상된다. 해당 글에서 정확히 어떤 상황에 지연이 발생했고, 해결한 뒤에 어떠한 현상이 개선된건지에 대 캐싱으로 해결한다면 아래와 같은 이슈에 대해서는 어떻게 해결했는지에 대해서는 언급되지 않는다.
