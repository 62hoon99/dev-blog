# 들어가며
최근들어 출근 해서 10분 정도 요즘 IT에 접속하여 아티클을 읽고있습니다.
재밌게 읽었던 아티클 중 [이메일 인증은 어떻게 구현하는 걸까?](https://yozm.wishket.com/magazine/detail/3515/)를 읽게 되었고, 내용이 재미있어서 아티클에 나와있는 이메일 인증 종류 별로 실제 기능을 구현해보고자 합니다.

## 이메일 인증이란?
아래는 제가 받았었던 듀오링고의 이메일 인증 메일입니다. 듀오링고 처럼 버튼을 눌러서 하는 이메일 인증, 이메일에 비밀번호를 전달해서 비밀번호를 입력하도록 하는 인증 등 이메일 인증 방식은 여러가지가 있습니다.

제가 읽었던 아티클에서는 "위험의 무게"에 따라, 메일 인증을 어떻게 다르게 하면 좋을지에 대해 나와있었는데요. 그럼 이제부터 메일 인증 종류 별로 어떤 장단점과 "위험"이 존재하는 지 정리해보고 직접 만들어보겠습니다.

# 가장 단순한 인증: 숫자 여섯자리를 직접 입력하기
메일 인증 중 제일 간단하고 쉬운 방법입니다. 구현 방법은 랜덤으로 숫자 여섯 자리를 만들어서 DB에 저장해두고, 사용자가 입력한 값이랑 같은지 비교하면 됩니다. 특정 정보를 암호화할 필요도 없고, 유효시간 정도만 처리하면 됩니다.

## 사용자 플로우
```
[이메일 입력 페이지 접속]
        ↓
이메일 입력 → "인증메일 보내기" 클릭
        ↓
"인증번호 입력 페이지" 이동
  화면: 인증번호 입력란 / 재전송 버튼 / 남은 시간 표시
        ↓
사용자 메일함으로 이동
        ↓
메일 열기 → 6자리 코드 확인
        ↓
웹 페이지로 돌아와 6자리 숫자 입력
        ↓
[ 확인 버튼 클릭 ]
        ↓
(성공)
→ 인증 완료 페이지
→ 로그인 / 다음 단계 진행

(실패)
→ 실패 메시지 표시
→ 남은 시도 수 차감 표시
→ 재입력 or 재전송
```
